# Lab 10: jwt-ciba

Require explicit approval for narrow write access.

## Starting point

Run `make prepare LAB=10 RUNTIME=podman` (or Docker). Use the same INSTANCE and PORT_BASE in every command. Preparation leaves lab 09 completed and this exercise unsolved.

Read [the command and custody guide](../docs/automation/usage.md). Learner code is `.build/<INSTANCE>/backend/connector.js`; runtime environment is `.secrets/<INSTANCE>/backend.env`. Keep credentials private. An initialized instance has recovery credentials in its private init.json; manual administrative work is explicit, while automation uses scoped identities.

## Exercise

Add the PostgreSQL support-write group with SELECT/UPDATE only on orders and a matching RLS condition limiting it to public/internal rows. Define short-lived Vault support-write credentials and add that exact path to the backend JWT policy. Enable Keycloak CIBA grant and polling/delegation configuration. Use the existing /ciba callback flow to gate a write on a matching approved session; pending and denied sessions must fail. Preserve role-scoped reads. Explain the application enforcement boundary: the backend's Vault identity can request write credentials, while approval is checked by the application.

After editing connector code, restart the instance backend using Compose. After editing backend.env, recreate it so the environment is reloaded. With default instance and Podman:

```sh
podman compose --env-file config/defaults.env --env-file .env -f .secrets/workshop/compose.yml -p zt-workshop up -d --no-deps --force-recreate backend
make verify LAB=10 RUNTIME=podman
```

Use `docker-compose` in place of `podman compose` for standalone Docker Compose. Adapt paths/project when using another INSTANCE. The verifier checks behavior; it never applies the solution. Probes may create temporary login/lease records and, for CIBA, one uniquely named test order that is deleted afterward.

## Hints

Inspect `data/connector.jwt-ciba.js`, the manifest's required features and existing subsystem docs. Use API/SQL observations to diagnose failures rather than changing completion markers. Preserve getCredentials and the optional lifecycle exports consumed by the existing pool manager.

## Reference solution

To intentionally replace your work, use `make resolve LAB=10 RUNTIME=podman OVERWRITE=1`. Edited connector files are backed up privately. Inspect `ansible/tasks/`, `ansible/library/`, `terraform/workshop/` and the local connector example to understand each change. Manually created mounts/policies require explicit `make adopt LAB=10` before later automated resolution; verification itself never requires adoption.
