# Lab 01: wired

Inspect hardcoded database credentials.

## Starting point

Run `make prepare LAB=01 RUNTIME=podman` (or Docker). Use the same INSTANCE and PORT_BASE in every command. This is the wired inspection baseline.

Read [the command and custody guide](../docs/automation/usage.md). Learner code is `.build/<INSTANCE>/backend/connector.js`; runtime environment is `.secrets/<INSTANCE>/backend.env`. Keep credentials private. An initialized instance has recovery credentials in its private init.json; manual administrative work is explicit, while automation uses scoped identities.

## Exercise

Inspect the generated connector. Identify the hardcoded username/password and explain where the same database identity is reused. Query `/users` and `/credentials` to establish the baseline. No code change is required for this inspection exercise.

After editing connector code, restart the instance backend using Compose. After editing backend.env, recreate it so the environment is reloaded. With default instance and Podman:

```sh
podman compose --env-file config/defaults.env --env-file .env -f .secrets/workshop/compose.yml -p zt-workshop up -d --no-deps --force-recreate backend
make verify LAB=01 RUNTIME=podman
```

Use `docker-compose` in place of `podman compose` for standalone Docker Compose. Adapt paths/project when using another INSTANCE. The verifier checks behavior; it never applies the solution. Probes may create temporary login/lease records and, for CIBA, one uniquely named test order that is deleted afterward.

## Hints

Inspect `data/connector.wired.js`, the manifest's required features and existing subsystem docs. Use API/SQL observations to diagnose failures rather than changing completion markers. Preserve getCredentials and the optional lifecycle exports consumed by the existing pool manager.

## Reference solution

To intentionally replace your work, use `make resolve LAB=01 RUNTIME=podman OVERWRITE=1`. Edited connector files are backed up privately. Inspect `ansible/tasks/`, `ansible/library/`, `terraform/workshop/` and the local connector example to understand each change. Manually created mounts/policies require explicit `make adopt LAB=01` before later automated resolution; verification itself never requires adoption.
