# Lab 04: approle

Authenticate a machine through scoped AppRole.

## Starting point

Run `make prepare LAB=04 RUNTIME=podman` (or Docker). Use the same INSTANCE and PORT_BASE in every command. Preparation leaves lab 03 completed and this exercise unsolved.

Read [the command and custody guide](../docs/automation/usage.md). Learner code is `.build/<INSTANCE>/backend/connector.js`; runtime environment is `.secrets/<INSTANCE>/backend.env`. Keep credentials private. An initialized instance has recovery credentials in its private init.json; manual administrative work is explicit, while automation uses scoped identities.

## Exercise

Enable AppRole at `approle`. Write `app-policy` with read access to `secret/data/postgres` and token self-management; create role `zero-trust-app` using that policy. Issue a role ID and secret ID and save them only in the private backend.env as VAULT_ROLE_ID and VAULT_SECRET_ID. Replace the application's static-token flow with AppRole login followed by KV access. Return source `vault-approle`. Verify that the resulting token cannot manage mounts or bootstrap policies.

After editing connector code, restart the instance backend using Compose. After editing backend.env, recreate it so the environment is reloaded. With default instance and Podman:

```sh
podman compose --env-file config/defaults.env --env-file .env -f .secrets/workshop/compose.yml -p zt-workshop up -d --no-deps --force-recreate backend
make verify LAB=04 RUNTIME=podman
```

Use `docker-compose` in place of `podman compose` for standalone Docker Compose. Adapt paths/project when using another INSTANCE. The verifier checks behavior; it never applies the solution. Probes may create temporary login/lease records and, for CIBA, one uniquely named test order that is deleted afterward.

## Hints

Inspect `data/connector.lab-approle.js`, the manifest's required features and existing subsystem docs. Use API/SQL observations to diagnose failures rather than changing completion markers. Preserve getCredentials and the optional lifecycle exports consumed by the existing pool manager.

## Reference solution

To intentionally replace your work, use `make resolve LAB=04 RUNTIME=podman OVERWRITE=1`. Edited connector files are backed up privately. Inspect `ansible/tasks/`, `ansible/library/`, `terraform/workshop/` and the local connector example to understand each change. Manually created mounts/policies require explicit `make adopt LAB=04` before later automated resolution; verification itself never requires adoption.
